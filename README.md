# 🧾 كاشير برو — نظام إدارة نقاط البيع المتكامل

نظام كاشير احترافي متكامل مبني بـ **HTML + JavaScript** (بدون إطار عمل) مع قاعدة بيانات **Supabase**، مع **تطبيق Flutter** يعمل كماسح باركود يرسل المنتجات لحظياً إلى الموقع.

| | الرابط |
|---|---|
| 🌐 الموقع (GitHub Pages) | https://taharbn12.github.io/t123/ |
| 📖 دليل الاستخدام المختصر | https://taharbn12.github.io/t123/guide.html |
| 📱 تحميل APK (رابط دائم) | https://github.com/TaharBn12/t123/releases/download/latest/cashier-scanner.apk |

## 📁 هيكل المشروع
```
web/        ← الموقع (HTML/JS/CSS) — يُنشر تلقائياً على GitHub Pages
app/        ← تطبيق Flutter للماسح — يُبنى APK تلقائياً في Releases
supabase/   ← schema.sql: الجداول، الدوال، سياسات الحماية RLS
.github/    ← workflows النشر التلقائي
```

## 🚀 خطوات التشغيل (مرة واحدة)

### 1) قاعدة البيانات
1. افتح لوحة Supabase → **SQL Editor**
2. الصق محتوى `supabase/schema.sql` واضغط **Run**
   - الملف آمن لإعادة التشغيل: يمكنك تنفيذه مرة أخرى بعد أي تحديث (يضيف فقط ما هو ناقص)
   - **أعد تشغيله بعد كل تحديث**: يرحّل القيود القديمة تلقائياً — مثل قيد وجهات المسح `scan_events.target` الذي صار يقبل `product` و`purchase` و`returns` (بدون ذلك تبقى عمليات المسح في طابور الهاتف)
   - ينشئ تلقائياً Bucket عام باسم `products` لصور المنتجات مع سياسات الحماية الخاصة به
3. **Authentication → Providers → Email**: يمكنك تعطيل "Confirm email" لتسهيل إنشاء الحسابات

### 2) GitHub Pages
- **Settings → Pages → Source**: اختر **GitHub Actions**
- كل push على `main` داخل `web/` ينشر الموقع تلقائياً

### 3) APK
- كل push داخل `app/` على `main` يبني APK ويرفعه على Release بوسم `latest` — الرابط أعلاه ثابت لا يتغير
- طلبات السحب التي تعدّل `app/` تُشغّل البناء أيضاً (بدون نشر) للتأكد قبل الدمج

**بناء محلي (اختياري):**
```bash
cd app
bash tool/prepare_android.sh   # يولّد ملفات Gradle/wrapper الأيقونات من قوالب إصدار Flutter لديك
flutter build apk --release    # الناتج: build/app/outputs/flutter-apk/app-release.apk
```
> ملفات منصة أندرويد المولَّدة (Gradle wrapper، الأيقونات، ملفات البناء) لا تُخزَّن في المستودع،
> لأنها تعتمد على إصدار Flutter؛ السكربت يولّدها ويُبقي ملفاتنا المخصّصة (AndroidManifest, MainActivity, styles).

### 4) أول مستخدم
- افتح الموقع → **حساب جديد** → أول حساب يُسجَّل يصبح **مدير النظام** تلقائياً، والباقي "كاشير" حتى تغيّر صلاحياتهم من صفحة المستخدمين.

## 🔒 الحماية
- **Row Level Security** على جميع الجداول: لا وصول بدون تسجيل دخول
- الحذف للمدراء فقط، الإعدادات والخصومات للمدراء، تعديل الصلاحيات للأدمن فقط (يُفرض في قاعدة البيانات لا في الواجهة)
- الحسابات المعطّلة تُمنع من الكتابة على مستوى قاعدة البيانات
- عمليات البيع تتم داخل دالة SQL واحدة (Transaction) لمنع تلاعب المخزون
- **Content-Security-Policy** في كل صفحة، تهريب كل النصوص ضد XSS
- تنظيف مدخلات الباركود، تحديد حجم/نوع الصور المرفوعة
- تأخير المحاولات الفاشلة عند تسجيل الدخول
- **لا يمكن لأي مستخدم رفع صلاحياته**: تغيير `role` أو `is_active` مسموح لمدير النظام فقط (trigger في قاعدة البيانات)
- دوال `security definer` (`complete_sale`, `adjust_stock`, `dashboard_stats`) تُنفَّذ للمستخدمين المفعّلين فقط، وممنوعة عن `anon`
- تحقق من صحة الأصناف داخل دوال البيع (كمية موجبة، سعر غير سالب) لمنع التلاعب بالمخزون
- سياسات تخزين خاصة بالصور: الكتابة للمستخدمين المفعّلين، والحذف للمدراء
- سكربتات الواجهة كلها خارج ملفات HTML (سياسة CSP صارمة: بلا `unsafe-inline` ولا سكربتات مضمّنة)
- مفتاح `anon` عام بطبيعته (Supabase مصمم لذلك) — الحماية الحقيقية عبر RLS

## 📱 تطبيق الماسح (Flutter)
- تسجيل دخول بنفس حساب الموقع
- **6 وجهات** يختارها المستخدم، ولكل وجهة قناة مستقلة في الموقع
- مسح متواصل (أو مسح واحد ثم تأكيد)، كشاف، تبديل الكاميرا، تكبير، اهتزاز وصوت
- إيقاف مؤقت / استئناف، إدخال باركود يدوياً، سجل المسح مع إعادة الإرسال والحذف
- إعدادات محفوظة على الجهاز: مهلة تجاهل التكرار (0–10 ث)، الكمية الافتراضية (1–50)
- عرض المنتج فور المسح (الاسم/السعر/المخزون)
- طابور محلي عند انقطاع الإنترنت ويُرسل تلقائياً عند العودة، مع عرض سبب الفشل إن وُجد

### الوجهات الست (هاتف ↔ صفحة)
| الوجهة في التطبيق | الصفحة في الموقع | ما يحدث عند المسح |
|---|---|---|
| `pos` | نقطة البيع | يُضاف المنتج إلى السلة بالكمية الممسوحة |
| `product` | إضافة / تعديل منتج | يُملأ حقل الباركود (مع تنبيه إذا كان مسجلاً لمنتج آخر) |
| `purchase` | المشتريات | يُضاف سطر إلى فاتورة الشراء المفتوحة |
| `inventory` | الجرد والمخزون | تُفتح نافذة تعديل المخزون بكمية مسبقة |
| `returns` | المرتجعات | يبحث عن آخر فاتورة تحوي هذا الباركود |
| `products` | استقبال المسح | يعرض بطاقة المنتج لحظياً |

كل صفحة تعرض شارة «استقبال من الهاتف» بنقطة خضراء عندما تكون مشتركة، وتتجاهل عمليات المسح المرسلة لوجهة أخرى.

### كيف يعمل الربط؟
التطبيق يُدرج سطراً في جدول `scan_events` (مع `target` و`quantity`) → الموقع مشترك عبر **Supabase Realtime** على قناة `scan-bridge-<target>` → يُعالَج الحدث في الصفحة المطابقة ثم يُعلَّم `consumed` حتى لا يُعاد.

> ⚠️ **بعد كل تحديث**: أعد تشغيل `supabase/schema.sql` في **SQL Editor**. الوجهات الجديدة (`product`, `purchase`, `returns`) مرفوضة من قيد CHECK القديم، والملف يحتوي ترحيلاً آمناً يحدّثه (`scan_events_target_check_v2`). بدون هذه الخطوة تبقى عمليات المسح في طابور الهاتف.
